# research.who-young.top — Populus Hu 的科研记录

纯静态站点。**首页的卡片与目录、每个项目页，全部由一个本地写字板生成**，
线上没有任何构建步骤。

线上地址：<https://research.who-young.top/>

> 这个仓库只包含**科研记录**这一个子站。主站 `who-young.top`、
> 工具箱 `tools.who-young.top` 分别是另外两个仓库。

---

## 它解决什么问题

实验记录最麻烦的不是写，是**攒**：过程写在笔记本里、数据在仪器导出的 txt 里、
分析脚本在另一个文件夹里，过半年就串不起来了。

这里把「一个项目 = 一篇长文」定死，正文用 Markdown 写，
目的 / 装置与参数 / 步骤 / 原始数据 / 分析 / 结论 用小节分开。
写字板负责把这些编译成静态页面，并**顺手重建首页**：

- 首页每张卡片是一个项目，卡片上直接列出该项目的**章节目录**，点一下直达对应小节
- 项目页带侧栏目录（滚动时高亮当前小节）、上下篇导航、代码高亮、带编号的插图
- 首页底部还有一份「完整目录」，可折叠地列出所有项目的所有小节

因为生成物是普通 HTML，所以它同时满足：能离线打开、能被搜索引擎抓到、
不会因为哪天某个 SaaS 停服而丢掉。

│   ├── research.js             目录高亮 / 代码复制 / 图片灯箱 / 状态筛选 / Mermaid
│   ├── lang.js                 多语言实现（与主站、工具站同一套机制）

因为部署方式是「从分支部署」，线上不做构建（见下面「部署」一节）。

## 日常使用：写字板

```bash
python tools/writepad.py
```

Windows 上直接双击 `tools/start-writepad.bat` 也行（它会先切到 UTF-8 再启动，
不然中文在控制台里是乱码）。

### 界面

- **左上角** 项目下拉框，切换项目；右边的按钮依次是
  新建 / 删除 / 保存 / 生成此页 / 重新生成全部 / 预览 / 预览首页 / 自检 /
  打开输出目录 / 站点设置
- **左栏** 元数据：标题、路径、日期、状态、图标、颜色、标签、摘要、封面、排序
- **右栏** 正文，上面一排插入按钮（标题、加粗、代码块、表格、图片、Mermaid……）
- **底部** 运行日志：每次生成都会把「生成了哪些文件、多少字、用了什么特性」打出来

### 快捷键

| 按键 | 作用 |
|---|---|
| `Ctrl+S` | 保存（写回 `content/<slug>/`） |
| `Ctrl+Enter` | 保存 → 生成这个项目 → 重建首页 |
| `F5` | 浏览器预览当前项目 |
| `Ctrl+B` / `Ctrl+I` / `Ctrl+K` | 加粗 / 斜体 / 链接 |
| `Ctrl+Z` | 撤销（正文框开了多级撤销） |

### 几个行为约定

- **「更新」日期自动跟着走**。正文内容变了才自动刷成今天，只改标题不会动它；
  左栏有开关可以关掉，也可以手动填。
- **改「路径」等于改目录名和网址**。保存时会把 `content/<旧路径>/` 改名、
  把 `meta.json` 里的 slug 同步、并删掉旧的 `/<旧路径>/` 页面。
- **删除不是真删**。项目会被挪到仓库根的 `.writepad-trash/`，
  那里已被 `.gitignore` 忽略，所以不会被发布出去，反悔了还能捞回来。
- **路径只能用「小写字母、数字、连字符」**。中文标题写在标题里，不影响显示。
  输入中文路径会被明确拒绝，而**不会**被悄悄改成别的名字。
  原因是 GitHub Pages 能把中文路径服务出去，但地址会变成一长串
  `%E8%96%84%E8%86%9C…`，分享和记笔记时都很难用。
- **预览走本地 HTTP，不走 `file://`**。生成出来的页面引用的是 `/assets/...`
  这种根路径，`file://` 打开会全崩。写字板内置了一个只监听 `127.0.0.1`
  随机端口的只读服务器，只服务本仓库目录，关窗时自动关掉。
- **插入图片会复制文件**。选中本地图片后，会复制到
  `content/<项目>/images/`，并插入形如 `![图名](images/xxx.png "")` 的一行 ——
  末尾那对引号是留给图注的，填进去就会显示在图片下方。

## 正文语法（Markdown 子集）

渲染器是自己写的（只用标准库），支持的是下面这些。**没有装 Markdown 库也能跑**，
这是刻意的：写字板必须在一台什么都没装的机器上直接可用。

| 写法 | 效果 |
|---|---|
| `# ~ ######` | 标题。**自动生成锚点**，二级三级标题会进侧栏目录与首页卡片 |
| 空行分段 / 行尾两个空格 | 段落 / 硬换行 |
| `**粗体**` `*斜体*` `~~删除~~` | 强调。`file_name` 这种下划线连接**不会**被当成斜体 |
| `` `行内代码` `` | 行内代码（内部不再解析其它标记） |
| ``` ```python … ``` ``` | 代码块，带语言名则用本地的 highlight.js 上色，右上角有复制按钮 |
| ``` ```mermaid … ``` ``` | 流程图 / 时序图等，用本地 mermaid 渲染 |
| `-` `*` `+` / `1.` | 无序、有序列表，缩进即嵌套 |
| `- [ ]` / `- [x]` | 任务列表（渲染成打勾框，不可交互） |
| `>` | 引用块 |
| `\|` 表格 | 表格，分隔行里的 `:` 控制对齐；窄屏可横向滚动 |
| `![替代文字](图片 "图注")` | **单独占一段**时变成带编号的 `<figure>`：自动加「图 1 / 图 2」 |
| `[文字](链接)`、`<https://…>`、裸 `https://…` | 链接，站外自动加 `target="_blank"` |
| `---` | 分隔线 |
| `<details>…</details>` | 原始 HTML 块原样透传（自己写的，风险自负） |

**不支持**：数学公式（LaTeX）、脚注、定义列表、行内 HTML 以外的高级 HTML。
科研记录里真需要公式，建议截图或写成代码块 —— 写进来会让渲染器复杂一大截。

### 图注的几个约定

- 图片**单独占一段**才会升级成插图并自动编号；夹在句子中间的图片就是普通行内图
- 编号是自动的，**图注里不要再手写「图 N」**；真的手写了也不会重复编号
- 图注为空时用替代文字（`![]` 里的第一段）当图注
- 点击插图会打开灯箱大图，`Esc` 关闭
- 图片文件放在 `content/<项目>/images/` 下，生成时整目录复制到 `/<项目>/images/`

## 项目元数据（`meta.json`）

写字板会维护这个文件，一般不用手改。

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | 字符串 | 标题，显示在卡片、项目页、浏览器标签上 |
| `slug` | 字符串 | 路径，与目录名一致；只允许小写字母、数字、连字符 |
| `date` | `YYYY-MM-DD` | 创建日期 |
| `updated` | `YYYY-MM-DD` | 更新日期，首页按它排序与显示 |
| `status` | 枚举 | `active` / `done` / `paused` / `planned` / `archived` |
| `tags` | 字符串数组 | 标签，显示为等宽小胶囊 |
| `summary` | 字符串 | 摘要，显示在首页卡片上 |
| `icon` | 字符串 | Font Awesome 类名，如 `fa-flask`；写字板里有中文说明的下拉表 |
| `color` | 枚举 | `blue` / `pink` / `green` / `lav` / `amber` / `gray`，卡片图标底色 |
| `cover` | 字符串 | （可选）封面图，相对项目目录，如 `images/cover.png`；卡片顶部通栏显示 |
| `order` | 整数 | 排序，**数字小的靠前**，默认 100 |
| `pinned` | 布尔 | 置顶，排在所有非置顶项目之前 |

排序规则：置顶 → `order` 升序 → `updated` 降序 → 标题。

## 生成器命令行

写字板是主要入口，`research_core.py` 留了命令行给批量和排错用：

```bash
python tools/research_core.py build             # 重新生成整站
python tools/research_core.py build <slug>      # 只生成某个项目 + 首页
python tools/research_core.py check             # 整站自检
python tools/research_core.py list              # 列出所有项目（状态 / 字数 / 标题）
python tools/research_core.py new <slug> [标题]  # 新建项目骨架
```

什么时候用命令行：换了样式表、改了 `_site.json`、或者从别处搬来一批
`content/` 之后，跑一次 `build` 全部重刷。

## 自检都查什么

`check`（写字板里的「自检」按钮）会跑九类检查，任何一条不过都会指到具体文件和键名：

1. **语言包键一致性** —— `en` / `jp` 有没有漏掉 `cn` 里的键
2. **用到的键都存在** —— 页面写了 `data-i18n="xxx"`、语言包里却没有
3. **生成页面的链接都指向存在的文件**（包括 `/slug/#锚点` 里的锚点是否真有对应 `id`）
4. **没有行内 `style`** —— 本站约定：一切视觉状态靠加类名
5. **没有引用外部 CDN 的资源** —— 正文里的参考文献链接不算
6. **每个项目目录是否合乎约定**（有没有 `meta.json`、`article.md`、
   日期格式、状态取值、封面图是否存在）
7. **正文引用的图片是否真的存在**
8. **HTML 兜底原文与 `cn` 语言包逐条一致** —— 这个错误肉眼几乎发现不了：
   页面看着完全正常，只有在禁用 JS 或语言包没加载时才露出旧文案
9. **页面用到的类名在 CSS 里都有样式** —— 防止「HTML 写了 class 但样式没跟上」
   这种静默走版（写模板时最容易漏）

另外还会提示两类**参考信息**（不算错误）：语言包里当前没被用到的键、
CSS 里当前没用到的类。很多是「有条件才渲染」的 ——
筛选按钮只在存在该状态的项目时才出现，语言切换只在有多个语言版本时才出现。

## 测试

改过 `research_core.py` 里的渲染器、或者动过 `research.css` 之后，跑这两个脚本：

```bash
python tools/tests/test_core.py        # 50 项断言
python tools/tests/test_writepad.py    # 46 项断言（会闪一下 tkinter 窗口）
```

它们不依赖任何第三方包，也不需要起服务器。两个脚本都会在 `content/` 下
临时建项目、结束时删掉并把站点重建回原样，**不会碰你已有的项目**。

第一个测的是生成核心，重点是渲染器里那些容易写错的地方：嵌套列表、
表格里的 `\|` 转义、图注自动编号、重复标题的锚点去重、
裸 URL 结尾的中文句号、行内代码里不该再解析标记、`file_name` 不该变成斜体……
以及首页那些「有条件才渲染」的分支（多状态筛选、上下篇、多语言、没有二级标题、空站）。

第二个测的是写字板本身：载入项目后表单是否正确、插入工具产出的 Markdown 对不对、
保存是否真的落盘、改路径是否真的把目录改名、「更新」日期是否按预期自动刷新、
非法输入（中文路径、错日期、非整数排序）是否被明确拒绝、
内置预览服务器能不能真的把页面取回来。

> 这两个脚本也会被「从分支部署」发布出去。都是纯源码，无所谓；
> 介意的话可以在 Pages 设置里改用 Actions 部署并过滤掉 `tools/`。

## 多语言

界面文案走与主站、工具站**完全相同的一套机制**：
`data-i18n="键名"` + `lang/{cn,en,jp}.json`，由 `assets/lang.js` 独家负责。

**现状**：正文只有中文；`lang/en.json` 与 `lang/jp.json` 目前是 `cn.json` 的镜像，
由生成器在文件缺失时创建。这样非中文浏览器不会因为 `/lang/en.json` 404
而在控制台刷警告，也不会看到「界面翻了一半」的样子。
要出英文版时，**直接把 `en.json` 里的值换成英文即可**，生成器只在文件不存在时才写。

**正文要多语言**：在项目目录里放 `article.en.md` / `article.jp.md` 就行，
生成器会自动产出 `/slug/en/` 与 `/slug/jp/`，并在项目页顶部加上语言切换入口。
（写字板目前只编辑中文正文，英文正文暂时手写。）

## 部署

**这个仓库不需要 GitHub Actions** —— 没有构建步骤，页面在本地就生成好了，
所以直接用分支部署：

```
Settings → Pages → Build and deployment → Source
  → Deploy from a branch
  → Branch: main   /   (root)
```

`CNAME` 文件的内容必须与 Settings 里的 Custom domain 一致（都是 `research.who-young.top`），
不一致会导致域名反复掉。

DNS 是在阿里云解析里加的（`research` 一条 CNAME 指向 `poplar-hu.github.io`），
源站在境外，**不需要备案**。

### 发布出去的内容包括 `content/` 和 `tools/`

分支部署会把整个仓库原样公开，「发布目录」就是仓库根。这里**没有敏感内容**：

- `content/` 是正文源文件 —— 它编译出来的 HTML 本来就要公开，源文件没有额外信息
- `tools/` 是生成器和写字板源码，纯本地工具，不含任何密钥
- 主站当初必须改用 Actions 部署，是因为仓库里躺着 `deploy/`（含服务器公网 IP）；
  这个仓库没有这类东西

如果哪天真的想藏起源文件，再改成 Actions 部署并在工作流里过滤即可 ——
但那时就要保证 CI 里也能跑生成器（它是纯标准库的，跑得起来）。

## 设计约定

样式刻意对齐前两个站：

- 背景渐变 = 主站 `src/css.css` 的 `.index-bg-pattern`
- 颜色令牌 = 主站 `tailwind.config.js` 的 `theme.extend.colors`
- 容器宽度、页眉页脚结构、hero 规格、卡片悬停位移、链接下划线动画都与工具站一致
- 字体栈相同（含 `PingFang SC` / `Microsoft YaHei` 回退）

两条硬约定：

1. **HTML 里不写行内 `style`**，状态一律靠加类名（`is-open` / `is-active` / `is-on`…）。
   自检里有一条专门查这个。
2. **不引用任何外部 CDN**。代码高亮、图表、图标字体全部本地化 ——
   断网也能打开，也不受境外 CDN 时快时慢的影响。

### 本地化的第三方库

| 文件 | 来源 | 大小 |
|---|---|---|
| `vendor/mermaid.min.js` | `npm/mermaid@11.4.1/dist/mermaid.min.js` | 2.5 MB |
| `vendor/highlight.min.js` | `npm/@highlightjs/cdn-assets@11/highlight.min.js` | 126 KB |
| `vendor/github.min.css` | `npm/@highlightjs/cdn-assets@11/styles/github.min.css` | 1.3 KB |
| `font-awesome.min.css` + `fonts/` | 复制自工具站（4.7.0） | 174 KB |

> mermaid 只在页面里真的出现 ```mermaid 代码块时才加载，
> highlight.js 也只在真的出现代码块时才加载 —— 两者都是 `defer`，
> 不阻塞首屏。`assets/research.js` 里判断这两个全局变量的代码
> 放在 `DOMContentLoaded` 里，因为在 `<head>` 里同步执行时它们还没定义。
